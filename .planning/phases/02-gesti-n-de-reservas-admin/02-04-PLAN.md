## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-17 | Elevation of Privilege | editarReserva | high | mitigate | First statement `await requireAdmin()`; RLS admin-only update; e2e: no-cookie POST changes nothing |
| T-02-18 | Information Disclosure (IDOR) | edit page | high | mitigate | Page `await requireAdmin()` + RLS; customer GET redirected (e2e); unknown/malformed id → 404 without leaking existence details |
| T-02-19 | Tampering | bound id / ownership columns | medium | mitigate | UUID re-validated server-side; the update is limited to the mapper's whitelist (never cliente_id, created_by, created_at); acceptance grep; e2e re-read |
| T-02-20 | Tampering | provider status vs payment | medium | mitigate | No pagos read or write in the actions (grep); e2e asserts the pago row is byte-identical after a status change (RESA-04 independence, prohibition 1) |
| T-02-21 | Tampering | con_problema without a note via raw POST | low | mitigate | zod rule + DB check `reservas_nota_problema_si_con_problema` (02-01); unit + e2e cases |
| T-02-22 | Tampering | silent status reset | low | mitigate | estadoProveedor required in the edit schema (a post missing it is rejected, never defaulted) |
</threat_model>
