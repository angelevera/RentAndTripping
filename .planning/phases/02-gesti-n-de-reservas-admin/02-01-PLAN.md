- **FA-2 — Edge probe RESA-02 (`unclassified` / `unresolved`).** Covered: unknown or malformed id returns 404 (02-04 T1), changing tipo replaces detalle (02-04 T1), editing never touches pagos, cliente_id or created_by (02-04), and a legacy row with an empty detalle still opens (02-04 T1). Needs human review.
- **FA-3 — Edge probe RESA-03 (`unclassified` / `unresolved`).** Covered: empty list, filtered-empty, load error, missing fecha_importante shown as "—", VES rows, 21 rows across 2 pages, a page number past the end, search wildcards typed literally (02-02, 02-05). Needs human review.
- **FA-4 — Edge probe RESA-04 (`unclassified` / `unresolved`).** Covered: confirmada with zero pagos; returning to pendiente while a confirmed pago exists; con_problema without a note rejected by both server and database; leaving con_problema clears the note (02-04 T2). Needs human review.
- **FA-5 — D-09 interpretation not confirmed word for word.** In the list, a VES-priced reserva shows the text "En Bs · ver detalle" (linking to its edit page) instead of an amount, and never a converted USD figure. Human-check in 02-02 T3.
- **FA-6 — RESEARCH A2, the "Pagado" rule.** The list shows "Pagado" when the reserva has at least one pago with estado 'confirmado', and "Pendiente" otherwise. Partial payments are Phase 4's concern. Human-check in 02-02 T3.
- **FA-7 — RESEARCH A3, the group-traveller fields.** D-03 needs a place to type how many people travel and their names, and the UI-SPEC field table (declared non-exhaustive) has none. Plan 02-03 adds "Cantidad de personas" and "Nombres de los viajeros (opcional)", stored inside detalle. Confirmed as part of option A in Task 1, plus a human-check in 02-03.
- **FA-8 — D-04 vs UI-SPEC on the traveller's phone.** It is required, per D-04. Raised in Task 1; changing it later is a one-line zod change with no database change.
- **FA-9 — Copy not in the UI-SPEC Copywriting Contract.** New strings are listed in each plan that introduces them (for example "Nueva reserva", "Editar reserva", section headings, "En Bs · ver detalle", "Todos los estados", "Todos los tipos", "Viaja: {nombre}", and field messages drafted in RESEARCH Pattern 2). Human-check at UAT.
- **FA-10 — No production deployment in this phase.** No Phase 2 requirement asks for one. The operator can only use the panel on his phone once the app is deployed (Vercel Pro, per the stack). Recommended decision before Phase 3; not planned here.
- **FA-11 — One hosted Supabase project for development and tests (continues Phase 1 FA-4).** Test reservas appear briefly in the same `/admin` list; they carry the rt-test- prefix and are removed after each run.
- **FA-12 — The JavaScript path of the shadcn form has no automated test.** The stack has no browser automation. Automated tests post the forms without JavaScript (the same server path); the in-browser flow is covered by human-checks in 02-03 and 02-04.
