# Phase 02 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Cubre las pantallas nuevas de esta fase: la lista de reservas (`/admin`, reemplaza el placeholder de Fase 1), el formulario de crear/editar reserva (`/admin/reservas/nueva` y `/admin/reservas/[id]/editar`), la barra de filtros/búsqueda sobre la lista, y las insignias (badges) de estado proveedor/pago. No cubre pantallas de cliente (Fase 3) ni de pago/comprobantes (Fase 4).

**Dispositivo:** ni CONTEXT.md ni el roadmap fijan un dispositivo específico para el admin de esta fase (a diferencia del mandato mobile-first del proyecto, que habla de los *clientes*). Este documento asume **mobile-first también para el admin** por defecto — el operador ya entra hoy desde el celular a Instagram/WhatsApp para gestionar todo — con un diseño que se adapta bien a pantallas grandes cuando las use. Esto es un valor por defecto razonable, no una decisión confirmada por el usuario; si el admin trabaja principalmente desde escritorio, vale la pena confirmarlo antes de construir.

```css

--color-marca-activo: #3D1F6F;  /* -15%, presionado */
--color-marca-suave: #7E66A8;   /* +30%, fondos suaves */
```

**Botones tipo pill:** shadcn's `Button` usa `rounded-md` por defecto. Los botones de **acción principal** (crear, guardar) deben sobreescribirse a `rounded-full` (pill morado, per idea.md §8) — los botones utilitarios (cancelar, paginación, quitar filtros) se quedan con el `--radius` estándar (12px), no pill. Esto reproduce a propósito la gramática de dos botones de Apple (pill = acción; rectángulo redondeado = utilidad) que también describe `DESIGN.md`.

**Transiciones:** todo botón usa `transition-transform` + `active:scale-95` (ya establecido en `login-form.tsx`) — nunca un cambio brusco. Los cambios de estado (ej. abrir el formulario de edición) usan un fundido breve (`transition-opacity`), no un salto instantáneo.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Espaciado entre icono y texto, gaps internos apretados |
| sm | 8px | Espaciado entre elementos compactos (label + input) |
| md | 16px | Espaciado por defecto entre campos, `padding` de fila de tabla en móvil |
| lg | 24px | `padding` de tarjeta/sección del formulario |
| xl | 32px | Separación entre secciones del formulario (pagador → viajero → tipo → precio) |
| 2xl | 48px | Separación mayor de página (`py-12` ya usado en `app/admin/page.tsx`) |
| 3xl | 64px | Reservado para espaciados de página completa, uso poco frecuente en esta fase |

Ya en uso en el código de Fase 1 (`gap-4`=16px, `gap-1`=4px, `px-4 py-12`=16px/48px) — esta fase reutiliza la misma escala, no introduce una nueva.

Exceptions: **44px mínimo** para todo objetivo táctil (botones, inputs, controles de fila) — ya establecido como `min-h-11` en `login-form.tsx`; se mantiene igual en esta fase, incluyendo el alto mínimo de cada fila/tarjeta de la lista para que "Editar" sea fácil de tocar en tablet.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 17px (Inter) | 400 | 1.47 |
| Label | 14px (Inter) | 600 | 1.3 |
| Heading | 20px (Poppins) | 700 | 1.2 |
| Display | 24px (Poppins) | 700 | 1.2 |

**Notas:**
- El tamaño de Body (17px) y su line-height (1.47) son los que ya fija `app/globals.css` desde Fase 1 (`body { font-size: 17px; line-height: 1.47 }`) — esta fase no los cambia, solo cambia la fuente detrás (de `system-ui` a Inter real).
- Máximo dos pesos **por familia**: Poppins solo usa 700 (títulos de página y de sección — cubre tanto `Heading` como `Display`, mismo peso, distinto tamaño); Inter usa 400 (cuerpo, inputs, celdas de tabla) y 600 (labels, encabezados de columna, botones, badges).
- `Display` (24px/Poppins 700) es el título de página ("Reservas", "Nueva reserva", "Editar reserva"). `Heading` (20px/Poppins 700) es un título de sección dentro del formulario (ej. "Quién paga", "Quién viaja", "Detalles del pasaje").
- Los inputs y el texto de las celdas de la tabla usan `Body` (17px/Inter 400) — mismo tamaño que ya usa `login-form.tsx` en sus `<input>`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` | Fondo de página, fondo de tabla, fondo de tarjetas de formulario |
| Secondary (30%) | `#f5f5f7` (pergamino) | Fondo de la barra de filtros, fila alterna de la tabla, fondo de inputs deshabilitados |
| Accent (10%) | `#482583` (marca) | Ver "Accent reserved for" abajo — único acento interactivo |
| Destructive | No aplica en el alcance de esta fase | Fase 2 no tiene eliminar/cancelar reserva; `--destructive` (`#b91c1c`) queda definido en el tema por completitud pero sin ningún botón que lo use todavía |

**Accent reserved for:** el botón "Crear reserva", el botón "Guardar reserva" / "Guardar cambios", los links de texto (ej. "Quitar filtros" cuando se muestra como link), el anillo de foco (`:focus-visible`, ya global), el checkbox/radio marcado, y el resaltado de la fila seleccionada en la tabla. Ningún otro elemento usa el morado — nunca en texto de cuerpo, nunca en fondos grandes, nunca en las insignias de estado (ver abajo).

**Excepción sancionada — colores semánticos de estado (no son un segundo acento):** las insignias (`badge`) de estado proveedor y estado de pago usan colores convencionales para que se lean de un vistazo, sin depender del texto. Nunca aparecen en botones, links ni ningún otro elemento interactivo — solo dentro del componente `badge`.

| Estado | Color de insignia |
|---|---|
| Proveedor: Pendiente | Gris neutro (`bg-gray-100 text-gray-700`) |
| Proveedor: Confirmada con el proveedor | Verde (`bg-green-50 text-green-700`) |
| Proveedor: Con problema | Rojo (`bg-red-50 text-red-700`) |
| Pago: Pendiente | Gris neutro (`bg-gray-100 text-gray-700`) — mismo que proveedor pendiente |
| Pago: Pagado | Verde (`bg-green-50 text-green-700`) — mismo verde que confirmada |
